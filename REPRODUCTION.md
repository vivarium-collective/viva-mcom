# Reproduction notes

`viva-mcom` is a **clean-room reproduction** of MCoM 1.0, not a wrapper around
the upstream engine. This document records exactly what was reproduced, from
what, and where the reproduction is known to differ.

## Provenance

| | |
|---|---|
| Model | Microbial Community Model (MCoM) v1.0 |
| Paper | Lücken, Follows, Bragg, Lennartz, *Geosci. Model Dev.* 19, 2461–2477, 2026 — [doi:10.5194/gmd-19-2461-2026](https://doi.org/10.5194/gmd-19-2461-2026) |
| Upstream code | <https://github.com/bgc-mod/MCoM>, v1.0.0, **commit `a39227c`** ("Adding files of version 1.0.0") |
| License | MIT, © 2025 bgc-mod |
| Archive | Zenodo [doi:10.5281/zenodo.19108362](https://doi.org/10.5281/zenodo.19108362) |

The upstream numerical core is **Julia** (`src/mcom.jl/`), orchestrated by a thin
Python runner. This reproduction re-implements that core in Python/NumPy so the
model runs without a Julia toolchain.

## What was reproduced, and from where

| This package | Upstream Julia source |
|---|---|
| `engine.derivatives` (RHS: phytoplankton, heterotrophs, DOC, DON, metabolites, N, carbon) | `src/mcom.jl/src/mcom_system.jl` |
| `engine.MComEngine.step` (2nd-order Adams–Bashforth, Euler bootstrap) | `src/mcom.jl/src/mcom_numerics.jl` + `main.jl` loop |
| `engine.make_fluctuation_function` (`constant`/`sinus`/`pulse`, summed with `+`) | `src/mcom.jl/src/mcom_io.jl:make_fct` |
| `config.instantiate_params` (scalar / degenerate-range / explicit / competing_pairs, `impute_nonzero_Ks`) | `src/mcom.jl/src/mcom_generator.jl` |

The RHS arithmetic follows the Julia source line-for-line, including the
phytoplankton exudation cases (Eqs 5–8), the heterotroph DOC-vs-N limitation
switch with/without surplus remineralization (Eqs 13–23), the metabolite
mortality feedback (Eq 9), and the carbon-conservation bookkeeping.

## Fidelity evidence

`datasets/golden/{test_tinit,test_save_offset}/` are trajectories generated by
the **real MCoM Julia engine** (shipped in the upstream test suite) together
with the exact config that produced them. `tests/test_golden.py` integrates the
same configs with this reproduction and asserts agreement to `< 1e-9` on time,
phytoplankton, and inorganic nitrogen. The observed difference is **0** (the
reproduction is bit-identical for these deterministic configs).

## Known divergences

1. **Random parameter draws are not reproduced.** A `[min, max]` parameter range
   with `min < max`, and the Dirichlet/simplex splitting of an un-normalized
   release/rate matrix across more than one connected compound, depend on Julia's
   Mersenne-Twister stream, which cannot be reproduced bit-for-bit in NumPy.
   `config.py` raises `NotImplementedError` where such a draw is required.
   Deterministic configs — scalars, degenerate ranges `[v, v]`, explicit values,
   single-edge networks, and `competing_pairs` diagonals — are exact.
2. **Randomised network link-counts are not reproduced** (`[network]` with numeric
   counts that select a random subset). Use `explicit = true` connectivity, or
   connect all compounds.
3. **Temperature rate modulation is a stub upstream** (`tempfac = 1.0` in
   `mcom_system.jl`); this reproduction keeps the same stub, so the
   `temperature` input port is accepted but does not (yet) modulate rates.
4. **DIN-supply noise** (`SourceNrnd`) uses NumPy's RNG, so a stochastic run's
   individual realisation will not match a Julia realisation (the deterministic
   `SourceNrnd = 0` case is exact).

## Validating against the real tool

To check this reproduction against upstream on a machine with Julia:

```bash
git clone https://github.com/bgc-mod/MCoM.git mcom && cd mcom
export MCOM_HOME=$PWD
julia -e 'using Pkg; Pkg.develop(path=ENV["MCOM_HOME"]*"/src/mcom.jl")'
pip install -r requirements.txt
python src/runner.py -c configs/test.toml       # writes output/run_test/dat/*.dat
```

then compare `output/run_test/dat/{P,H,N,...}.dat` against a
`MComEngine(...).run(...)` trajectory built from the same config.
